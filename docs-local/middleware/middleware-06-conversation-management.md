# 对话管理类中间件（处理逻辑）

本文件介绍负责"对话生命周期管理"的五款中间件：上下文压缩（Summarization）、待办追踪（Todo）、Token 归因（TokenUsage）、标题生成（Title）、记忆入队（Memory）。它们在主 Agent 中间件链中的位置见 `backend/AGENTS.md` 的 "Middleware Chain"（编号 18、19、20、21、22）。

---

## 1. DeerFlowSummarizationMiddleware

**职责**：当 token 逼近上限时，自动把较早消息压缩成 `summary_text` 摘要并保留近期窗口；压缩前派发钩子让记忆子系统抢救即将丢失的内容。

**处理逻辑**：

- 每次模型调用前检测 token 压力（**把已有摘要也算进总量**，避免摘要无限累积），逼近上限触发压缩。
- 三种 trigger：按 token 数 / 消息条数 / 最大输入比例；求出切割点后把消息分成"将被压缩"与"保留"两段。
- **压缩前抢救动态上下文**：识别 ID-Swap 三元组（带标记的 reminder 及其未带标记的真实用户消息 peer），单次扫描按时间序整组救出——防止三元组被拆散导致后续注入错位。
- **压缩前派发 `BeforeSummarizationHook`** 把待压缩消息投递到记忆队列（异步），即使消息被压成摘要，长期记忆仍保留原始事实；**hooks 只在"替换 summary 已存在"且"消息尚未移除"时触发**（防 summary 生成失败却重复提取）；子 Agent 链路显式跳过记忆冲刷，防子代理轮次写入父线程长期记忆。
- **保留最新真实用户请求**：按精确消息 ID 保留（ID-swap 中的 `__user` 未标记 peer 不救，让历史 prompt 仍可压缩）——否则跨多轮首次长分析的压缩可能变 no-op，或模型答错 turn。
- 摘要生成走独立模型属性并禁流式 tag（避免幻影 AI 消息广播前端）；保留归因 tag。
- **写摘要前对用户文本转义**（`<` `>` `&`），防 XSS 与块逃逸、防用户伪造权威段喂给抽取模型。
- 摘要预算按新旧各半分配；token 计数失败回退确定性文本裁剪（保证截断点不切分实体）。
- 摘要生成任意失败只记日志并放弃本轮压缩，**不把损坏摘要写进 checkpoint**。
- 手动强制压缩入口与 run 回放、目标写入共用同一 per-thread 串行锁，避免抢写 checkpoint。
- 摘要存独立 `summary_text` 通道而非 `messages` 历史；用"全清再追加"语义替换消息，避免残留。

## 2. TodoMiddleware

**职责**：待办追踪，防模型在待办未完成时草草结束。

**处理逻辑**：

- 待办列表经 `write_todos` 写入后若被压缩滚出窗口，`before_model` 检测"还有待办但 write_todos 调用已不可见且未提醒过"→ 注入一条"列表仍存在"的隐藏提醒，提醒写回 state、跨轮存活。
- 若已能再看到 write_todos 调用或已注入过提醒，则不重复注入。
- 模型在待办未完成时试图干净结束 → 检测工具调用意图（跨 LangChain 版本与 provider 兼容多种字段）与错误；只有"干净的最终答案"才触发，工具调用意图/解析错误放行走工具路径。
- 待办全部完成或无待办 → 放行。
- **结束提醒有重试上限（2 次）**，防模型反复"就要结束"造成死循环；到上限后放行让其给最终答案。
- 通过 `jump_to=model` 把控制权强回 model 节点继续工作；但提醒**不持久化为 state 消息**，而是在下一次模型调用前从内存队列追加到请求末尾（避免泄漏进用户可见消息流）。
- 计数与清理按 `(thread, run)` 键管理：新 run 开始清旧 run 残留，run 结束清自己；键数量超上限按 LRU 淘汰最久未访问项，保护长生命周期实例内存。

## 3. TokenUsageMiddleware

**职责**：记录 token 用量并做子代理归因，供计费/可观测。

**处理逻辑**：

- 每次模型响应后捕获用量元数据，从缓存取出子代理累积的 token 用量，**回填到派发它的那条 AI 消息**（同一步派发多个子代理时累加而非覆盖），并清缓存防重复归因。
- 从倒二条工具消息往回扫，只处理本步骤的工具结果；遇到非工具消息或无 id 即停。
- 为最新 AI 步骤构建结构化归因：按工具名路由成不同动作（待办增删改、子代理、搜索、展示文件、澄清提问、通用工具），并带动作类型、工具调用 id、子代理归因信息。
- 根据动作推断步骤类型：单个待办类→待办更新、单个子代理→子代理派发、多动作→批量工具、无动作有内容→最终回答、无动作无内容→思考。
- 待办动作通过对新老待办列表 diff 生成（优先按内容匹配防错配，内容未匹配退而按位置，完全一致跳过，未匹配旧项标为移除），是前端展示的单一真源。
- **幂等保护**：新归因与既有相同时跳过重建对象，减少 checkpoint 写入压力；stamp `subagent_token_usage_attributed=true` 防重放重复累加。
- 记录 INFO 级用量日志，带输入/输出明细（缓存命中、推理 token 等）。

## 4. TitleMiddleware

**职责**：首轮完整对话结束后自动为 thread 生成标题。

**处理逻辑**：

- 只在首轮后触发（第二轮起不重生成），已有标题不覆盖；分号计数排除隐藏 reminder（用户首条消息）。
- 配置了模型则用 LLM 生成结构化标题：注入模板（用户与回复各截 500 字符），关思考/tracing，禁流式 tag 防幻影流，并归因到标题中间件。
- 解析标题时剥离 reasoning 模型的 `<think>` 推理块、拍平多模态 content、去掉引号包裹、按最大字符截断。
- 无模型、LLM 失败或解析出空标题 → 本地回退：截取首条用户消息前 50 字符（留省略号空间保证不超长度），空消息返回 "New Conversation"。
- **同步路径只走本地回退不调 LLM**（防阻塞事件循环）；异步路径才走 LLM。
- **首轮被中断时**，run worker 在 finalizing 阶段独立调用本地回退生成标题并同步到展示名——保证 thread 总有名字，不停在 "New Conversation"。

## 5. MemoryMiddleware

**职责**：Agent 整轮结束后把本轮原始消息投递到记忆队列，由后端异步 LLM 抽取用户上下文与事实写入 per-user 记忆文件。中间件本身只入队、不抽取。

**处理逻辑**：

- `after_agent`/`aafter_agent` 把本轮原始消息交给 `manager.add()`；manager 去抖入队并立即返回——LLM 抽取在后台线程，**绝不跑在 agent loop 里**。
- 在请求上下文还活着时捕获 `user_id`——因为去抖 Timer 在独立线程运行、ContextVar 不跨线程传播，若到 Timer 才解析会拿到默认桶。
- `trace_id` 三级回退（运行时上下文 → RunnableConfig metadata → trace 上下文），覆盖 HTTP/嵌入/TUI 多入口，保证抽取调用在 Langfuse 里可与主对话关联。
- 无 thread_id 或无可处理消息时跳过。
- **后端负责**：过滤（仅用户输入+最终 AI 回复，排除工具调用消息与 hide_from_ui 框架消息）、校验、检测纠正/强化信号、per-thread 去重、去抖批量、LLM 抽取合并、原子写文件并失效缓存。
- **子 Agent 链路显式不装配本中间件**，防子代理轮次污染父线程记忆。
- 两种模式：middleware 模式走被动抽取（默认装配）；tool 模式本中间件不装配，改为 `memory_*` 工具让模型主动增删改查记忆；两者共享底层存储与 prompt 体系。
- 优雅停机时冲刷队列剩余项，不丢失待处理记忆。
